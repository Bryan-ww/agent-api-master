# 第 12 课 · RAG 原理：为什么"向量检索"比"关键词搜索"懂语义

> 目标：建立 RAG 的完整理论画面——Embedding 是什么、向量为什么能表达语义、chunk 为什么要分块、向量库（Qdrant）怎么存怎么查。不写代码，纯概念 + 动手小实验。前端类比：**Embedding ≈ 把文字变成"坐标"，向量检索 ≈ 在坐标系里找"离我最近的邻居"；RAG ≈ 先查资料再让 LLM 照着资料回答，而不是让它瞎编**。

---

## 12.1 RAG 解决什么问题

大模型的"知识"停在训练完成那一刻，且会一本正经地胡说（幻觉）。**RAG（Retrieval-Augmented Generation，检索增强生成）**的思路很朴素：

> 用户提问时，先到你的**私有知识库**里检索相关段落，把段落作为"参考资料"拼进 prompt，再让 LLM 基于资料回答。

```
用户问 → ① 检索：从知识库找出最相关的几段
       → ② 增强：问题 + 资料段落 拼成 prompt
       → ③ 生成：LLM 只依据资料回答（可注明"资料里没有"）
```

类比前端：**等于给没有业务知识的 AI 现场喂文档**。项目核心点 5 整条链路（上传 → OCR → 清洗 → 分块 → Embedding → 向量库 → 检索）都是为了支撑这个"找资料"的动作。

## 12.2 Embedding：把文字变成"坐标"

**Embedding = 把一段文字映射成一个向量（几百~几千维的浮点数数组）**。关键性质：**语义相近的文字，向量距离也近**。

```
"猫在睡觉"   → [0.12, -0.03, 0.87, ...]   ┐
"猫咪打盹了" → [0.13, -0.02, 0.85, ...]   ┼ 距离近（语义相似）
"股票大涨"   → [0.71, 0.22, -0.41, ...]   ┘ 距离远（语义无关）
```

- 它是**模型**算出来的（OpenAI embedding / BGE / M3E 等），不是规则匹配。
- 前端直觉：**相当于把文本塞进一个"语义空间"，得到坐标**。向量维度通常 768 / 1024 / 1536。
- 这也解释了为什么它比关键词搜索强：搜"猫在睡觉"，关键词搜"猫咪打盹了"匹配不上（没有共同词），但向量检索能找到（语义近）。

> ⚠️ 一个关键认知：**Embedding 模型 ≠ 聊天模型**。它们分工不同：聊天模型会"说话"，Embedding 模型只会"算坐标"。本项目用 `OPENAI_API_KEY` 同时驱动两者（`rag_service.py` 里 embedding 用 `Embeddings` 客户端），但模型名往往是不同的（如 `text-embedding-3-small` vs `gpt-4o-mini`）。

## 12.3 为什么必须"分块（chunk）"？—— 检索的粒度问题

如果把整本书（10 万 token）一次性 Embedding：
- 单条向量只表达"整本书"的模糊语义，用户问书里第 3 章某个细节，检索根本对不上（粒度太粗）；
- 大文本也超过 Embedding 模型的输入上限。

所以先把文档**切成小块**（本项目 `rag_service.py`：`chunk_size=2000` 字符、`chunk_overlap=200` 重叠），每块单独 Embedding、单独入库。检索时命中"最相关的块"，把这块文字喂给 LLM。

**为什么要有 200 字符的重叠（overlap）？** 防止一句话恰好被拦腰切断在两块里，导致哪块都不完整。重叠让"跨块的语义"至少完整落进其中一块。

## 12.4 向量数据库（Qdrant）干什么

普通数据库做不了"按向量距离找最近邻居"（高维空间最近邻搜索）。**向量数据库 = 专门为向量存储和 ANN（近似最近邻）搜索优化的库**。本项目用 **Qdrant**，核心概念（和第 06 课的表对照）：

| Qdrant 概念 | 类比 | 说明 |
|---|---|---|
| Collection（集合） | 一张表 | 存某一类向量。本项目 collection_name 存"RAG 文档块" |
| Point（点） | 一行 | 一条向量 + payload（元数据） |
| Vector（向量） | 一列 | 某文本块的坐标 |
| Payload | 普通列 | 元数据：原文 chunk、文件名、`user_id`（**用于多用户数据隔离**）、页码等 |
| 相似度度量 | - | 本项目用余弦相似度或点积（向量越近 = 越相关） |

检索时：用户问题 → Embedding 成向量 → Qdrant 返回**Top-K 最邻近的点**（带着 chunk 原文和 user_id 过滤条件）→ 取原文拼 prompt。
